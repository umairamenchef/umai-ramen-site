<task type="auto">
  <name>Task 1: Bundle analysis, build verification, and performance fixes</name>
  <files>
    next.config.ts
  </files>
  <action>
    **1. Install @next/bundle-analyzer (dev dependency):**
    ```bash
    npm install --save-dev @next/bundle-analyzer
    ```

    **2. Add bundle analyzer to next.config.ts:**
    - Import `withBundleAnalyzer` from `@next/bundle-analyzer`
    - Wrap the existing config: `const withBundleAnalyzer = require('@next/bundle-analyzer')({ enabled: process.env.ANALYZE === 'true' })`
    - Or use ESM import if next.config.ts uses ESM (check existing config format)
    - This is a dev-only tool; it does not affect production builds

    **3. Run production build and verify static generation:**
    ```bash
    NEXT_TURBOPACK_USE_WORKER=0 npx next build
    ```
    - Check build output: ALL content routes must show `○` (static/ISR), NOT `λ` (dynamic/server-rendered)
    - Expected static routes: `/[locale]` (homepage), `/[locale]/menu`, `/[locale]/reservation`, `/[locale]/commander`, `/[locale]/notre-histoire`, `/[locale]/infos`, `/[locale]/galerie`, `/[locale]/mentions-legales`, `/[locale]/politique-confidentialite`, `/[locale]/politique-cookies`, `/[locale]/cgv`
    - If any route shows `λ`: investigate and fix (likely missing `setRequestLocale` or dynamic import issue)
    - Record the First Load JS size for each route from build output
    - **PERF-05 check:** No route should exceed 150KB gzipped. If any does, investigate the largest chunks.

    **4. Run bundle analysis:**
    ```bash
    ANALYZE=true NEXT_TURBOPACK_USE_WORKER=0 npx next build
    ```
    - Review the generated `.next/analyze/` reports
    - Identify any unexpectedly large client-side bundles
    - Key areas to check:
      - `yet-another-react-lightbox` should be code-split (only loads on gallery page)
      - `schema-dts` should NOT appear in client bundles (types only, zero runtime)
      - `motion` should use LazyMotion (domAnimation ~4.6KB, not full ~34KB)
      - Cookie consent banner JS should be minimal (< 5KB)
      - No Sanity Studio code in client bundles (Studio is a separate route)

    **5. Verify image optimization (PERF-03):**
    - Check that all `<img>` tags in the built HTML use `/_next/image` URLs (next/image optimization)
    - Verify Sanity CDN URLs include `?auto=format` for WebP auto-conversion
    - Check for any images NOT going through next/image or Sanity CDN

    **6. Verify font loading (PERF-04):**
    - Check build output for font files in `/_next/static/media/`
    - Confirm no external font CDN requests (no fonts.googleapis.com or fonts.gstatic.com)
    - Verify DM Serif Display and Outfit have `preload: true`, Noto Sans JP has `preload: false`

    **7. Fix any issues found:**
    - If bundle size exceeds 150KB on any route: analyze imports, add dynamic imports where appropriate
    - If any route is dynamic instead of static: add missing `setRequestLocale` or `export const revalidate`
    - If images are not optimized: fix next/image usage
    - If fonts are externally loaded: fix next/font configuration
    - Document all fixes in the SUMMARY

    **8. CLS verification (PERF-02):**
    - Verify cookie consent banner uses `position: fixed; bottom: 0` (no layout shift)
    - Verify fonts use `display: swap` (configured in Phase 1, confirm still present)
    - Verify no images without explicit width/height or fill prop
    - Check hero image uses `loading="eager"` (not lazy — it's above the fold)

    **9. ISR end-to-end verification:**
    - Confirm the revalidate webhook handler is functional (from Plan 03-01)
    - Verify `revalidate = 60` is set on locale layout
    - Verify legal pages have `revalidate = false` (permanently cached)
    - Document the ISR flow: Sanity publish -> webhook POST -> revalidateTag -> next request serves fresh content

    **10. Production readiness checklist:**
    - [ ] Sanity Studio CORS: document that production domain must be added to Sanity project CORS settings (sanity.io dashboard)
    - [ ] Environment variables needed for production: `NEXT_PUBLIC_BASE_URL`, `NEXT_PUBLIC_GTM_ID`, `NEXT_PUBLIC_GA4_ID` (optional), `SANITY_WEBHOOK_SECRET`, `NEXT_PUBLIC_SANITY_PROJECT_ID`, `NEXT_PUBLIC_SANITY_DATASET`
    - [ ] OG image: an `/og-image.jpg` file should be placed in `public/` before launch (1200x630px)
    - [ ] Legal page placeholders: owner must replace [COMPANY NAME], [SIRET], etc.
    - [ ] Gusty Click & Collect URL: owner must provide and update in Sanity
  </action>

    3. No route exceeds 150KB gzipped first-load JS in build output
    4. Bundle analyzer report confirms no unexpected large client modules
