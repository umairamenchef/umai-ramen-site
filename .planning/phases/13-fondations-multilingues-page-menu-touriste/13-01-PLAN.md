next-intl 4.8.3 middleware facts (read in node_modules/next-intl/dist/esm/development/middleware/*.js):
- locale resolution = URL prefix, then cookie `NEXT_LOCALE` (if it is a routing locale), then Accept-Language matched against `routing.locales`, then `defaultLocale`.
- unprefixed paths (`/`, `/infos`, `/menu`) get `NextResponse.redirect()` (307) to `/{resolved}{path}`; prefixed paths get `next()`/rewrite (no Location).
- `syncCookie` sets `NEXT_LOCALE` when the cookie is outdated, or when there is no cookie and the Accept-Language locale differs from the resolved one (e.g. visiting `/zh/menu` with an English phone sets `NEXT_LOCALE=zh`).
- `alternateLinks` (default true) adds a `Link` response header with `hreflang` alternates for ALL routing locales on every non-redirect response. The live site sends it today (fr/en/de + `x-default` → unprefixed `/menu`).
